# 余烬对决 · 微信导入与验收

当前工程是原生微信**小程序**：入口为 `app.json`，工程配置 `compileType=miniprogram`。它不是 Canvas 微信小游戏工程。实际发行前，需确认目标平台、账号类目和相应资质；不能仅凭项目导入成功认定小程序或小游戏均可发布。若最终目标为小游戏，需要另行适配该目标的运行入口与界面。

## 1. 开发导出

使用 Node.js 18 或更新版本，在仓库根目录运行：

```sh
npm test
npm run verify
npm run package:weapp
```

工程没有第三方 npm 依赖，无需 `npm install` 或开发者工具「构建 npm」。游戏使用离线人机规则和本地 PNG 素材，不需要后端地址、云开发环境、数据库或额外密钥。

`package:weapp` 把以下显式允许项复制到 `.artifacts/wechat/card-battle-game`：

| 允许项 | 内容 |
| --- | --- |
| `app.js`、`app.json`、`app.wxss`、`game.js` | 原生入口、全局样式与规则 |
| `project.config.json`、`sitemap.json` | 工程配置与搜索规则 |
| `pages/` 的 JS、JSON、WXML、WXSS、WXS | 原生页面 |
| `data/` 的 JS、JSON | 卡牌文案与素材元数据 |
| `assets/` 的图片、音频、字体 | 原生使用的本地素材 |

浏览器入口、历史原型、设计源文件、测试、说明、Git、缓存和个人工程配置不进入开发导出。导出前检查 JSON/JS 语法、页面文件、静态本地 `require`、WXML 图片/模板导入、WXSS 引用和已声明的素材路径。动态图片仅支持可核查元数据的 `{{item.art}}` 等绑定；任意拼接资源表达式需先扩展校验器。卡牌和素材覆盖率由页面与项目回归测试进一步验证。

校验器拒绝符号链接、真实 `debugger` 语句、开启的 `app.json.debug`，以及实际路径位于 `test`、`fixtures`、`debug` 等目录或带测试后缀的原生资源；不会因为普通文案或注释包含“测试”“debug”等词而报错。新增原生组件目录、分包、插件、workers 等入口前，应先扩展允许清单及其完整性检查。

`scripts/package-weapp.js` 的 `MAX_MAIN_PACKAGE_BYTES` 默认为 `2 * 1024 * 1024`，这是仓库采用的保守体积预算，按未压缩原生文件总大小作硬限，超过即失败，不能靠 ZIP 压缩绕过。它不代表已经核实当前微信平台的全部体积规则；最终包大小以开发者工具编译分析及上传检查为准。校验器的只读 `validateProject(root, { maxBytes })` 接口供测试和其他发布工具复用；正式命令仍使用默认预算。

同目录另有 `card-battle-game.manifest.json`，记录文件大小和 SHA-256；系统安装了 `zip` 时同时生成 `card-battle-game.zip`。相同源码采用固定文件顺序和时间戳，重复打包可核对哈希。ZIP 是交付用源工程，不是微信官方上传包。

生成目录每次导出都会重建。请在源码内迭代，或把 ZIP 解压到单独维护的工作目录。若直接在生成目录修改，重新导出前先将改动回迁，避免丢失。

## 2. 导入与编译

1. 在 Windows/macOS 安装稳定版微信开发者工具，使用有权限的微信账号登录。
2. 选择「导入项目」，选 `.artifacts/wechat/card-battle-game`，或 ZIP 解压后的同名目录。该目录内应直接存在 `app.json`。
3. 工程类型选「小程序」，后端服务选「不使用云服务」。本地查看可选择工具提供的测试号；完整预览、体验版或上传使用自己有权限且类别正确的 AppID。
4. 小程序目录为 `./`，直接点击「编译」。首页由 `app.json` 指向 `pages/home/home`，无需另填编译入口。
5. 保持 ES6 转 ES5、增强编译和域名校验开启，使用当前稳定基础库开始验收。

也可直接导入仓库根目录开发，配置中的排除表会过滤非原生内容。开发者工具可能写入本机 AppID 和 `project.private.config.json`；这些属于个人配置，提交前应检查 Git 变更。测试号的真机及预览能力以工具提示为准。

## 3. 模拟器验收

从独立导出的目录编译，先确认控制台没有 JS/WXML/WXSS 错误、资源丢失或无效组件提示，再完成：

| 场景 | 预期 |
| --- | --- |
| 开始页 | 主题图、阵容与按钮完整，规则可展开/收起 |
| 进入战斗 | 六张卡牌和素材完整，己方先行动 |
| 攻击/目标选择 | 只能操作存活卡牌，每次动作只结算一次 |
| 龙焰 | 作用于所有存活敌人，本局不能重复释放 |
| 精准射击 | 可进入/取消技能目标选择，选定后正确结算 |
| AI 回合 | 己方无法抢行动，AI 动作后正常交还回合 |
| 击倒与结算 | HP 不小于零，倒下不可操作，结果与日志一致 |
| 重开 | HP、技能、日志重置，旧计时器不影响新一局 |
| 返回首页 | 再进对局时没有旧页面回调或重复导航 |
| 关于与隐私 | 版本及离线数据说明准确，可正常返回 |
| 窄屏 | 320/375/430 像素宽度下可读可点，页面正常滚动 |

至少完成一次胜利、一次失败和再次开局。浏览器的相似外观不能证明原生页面已通过微信编译。

## 4. 真机与最终设计验收

点击「预览」，使用有权限的微信扫码；测试号不支持该能力时，使用自己的真实 AppID。当前无网络请求，保持 `urlCheck` 开启即可。

分别在 iOS 和 Android 手机上完成一局，记录设备、系统、微信和基础库版本，并确认：

- 刘海屏、底部安全区和字体缩放下，文字、生命值、目标提示与主要按钮可见可点。
- 七张图片显示完整清晰，选中、目标、倒下、等待与结算状态容易区分。
- AI 思考中切后台再回来、离开页面再进入，没有重复行动、卡住或旧回调。
- 快速连点、取消技能、切换卡牌和重开时，动作锁与技能次数正确。
- 断网时仍能完成离线战斗；设计在设备上的最终效果符合预期。

使用「真机调试」记录异常和布局，再修改源码复测。最终设计验收应在设备上完成。

## 5. 发布候选检查

`npm run verify` 检查代码和测试，无需真实 AppID。准备候选时运行：

```sh
npm run release:check
npm run package:release
```

发布检查使用发布配置和真实 AppID，详细配置见 [发布候选流程](RELEASE.md)。`release.config.json`、`release.local.example.json` 和本机 `release.local.json` 均不进入原生运行时工程。不在聊天中提供密钥，不将开发者工具凭据保存到源码。缺少发布要求时，命令应失败并列出阻塞项，不产出冒充正式发布的包。

`package:release` 生成的是 release-candidate 源工程，不是微信官方上传包。候选检查通过后，仍须在有权限的开发者工具中完成官方编译、代码依赖/包体积分析、真机验收与上传。账号类目、内容与素材权属、平台要求和审核结果需按实际目标平台核实；候选包不代表平台已审核通过，也不会自动上传或发布。

## 6. 故障与验证边界

| 现象 | 处理 |
| --- | --- |
| 找不到 app.json | 选择直接包含该文件的目录，而非父目录 |
| AppID 无权限或不能预览 | 使用工具测试号本地查看，或由管理员授权正确账号/AppID |
| 提示构建 npm | 本项目不需要 npm 构建，直接编译 |
| 导出缺少模块/图片 | 修正源引用或补齐实际资源，不要略过检查 |
| 主包超限 | 压缩素材或正式设计分包，再更新导出允许清单 |
| 源码修改未同步 | 重新导出，或日常开发直接导入源码根目录 |
| 没有 ZIP | 安装系统 zip 后重跑，或直接复制完整工程目录 |
| 发布检查失败 | 按输出核实 AppID、配置和目标类别，再运行候选命令 |

云端可以验证规则、页面逻辑、结构/语法、引用完整性、大小、文件哈希及 ZIP；这些结果不等于微信官方编译证据。此环境没有 Windows/macOS 微信开发者工具、扫码会话或真机；Linux 也缺少微信 WXML/WXSS 官方编译器所需的原生插件。模拟器编译、iOS/Android 真机、扫码预览、上传和审核发布均需本地完成，不能标记为云端已通过。
