# 1.0.0 发布候选版交接

本轮先固定现有三对三单人玩法，交付可导入、可检查、可回归的原生工程。后续玩法迭代从这个版本继续。发布候选源工程不等于已通过微信编译、真机或审核的线上版本。

## 最短交接路径

下载并解压 `.artifacts/wechat/card-battle-game.zip`，在微信开发者工具导入直接包含 `app.json` 的文件夹，选择实际小程序 AppID，然后编译、真机验证、上传开发版本并在平台提交审核。微信开发者工具会自行生成上传包。下面的 Node 命令用于源码维护和自动化交付，已有导入包可以直接使用图形界面流程。

## 当前工程类型

此仓库的 `compileType` 为 `miniprogram`，使用 `Page()`、WXML、WXSS。导入时需要类型相符的小程序 AppID。

微信官方分别提供[小程序与小游戏模板](https://github.com/wechat-miniprogram/miniprogram-cli)，[小游戏示例](https://github.com/wechat-miniprogram/minigame-demo)使用 `compileType: game`、`game.js/game.json` 和 Canvas。小游戏账号不能只替换当前工程 AppID 后上传；若账号是小游戏，需要另做入口与渲染迁移，共享规则和美术可以复用。

当前没有确认你的账号类型、服务类目及审核资格。应以微信公众平台后台和官方答复核实此内容适合的发布路线。本轮能核对官方示例中的技术区别，未取得当前运营规范的完整原文，不据此宣称此小游戏玩法一定可以或一定不可以通过普通小程序审核。

## 1. 先验证源码与开发导出

在仓库根目录运行（Node.js 18+，无第三方依赖）：

```sh
npm run verify
npm run package:weapp
```

`verify` 运行测试和源码预检，验证路由、模块、素材、语法、版本一致性和保守包体预算。`package:weapp` 生成 `.artifacts/wechat/card-battle-game` 与 ZIP，保留源码 AppID，可先导入开发者工具检查。

工程内已有开始、规则、对局、技能、结算、再战、返回与关于/隐私说明。没有后端、账号登录、广告、支付或云开发依赖，无需构建 npm。源码预检不能替代微信编译器。

## 2. 填写本机发布账号配置

正式候选包使用单独的本机配置，避免修改共享项目文件：

```sh
cp release.local.example.json release.local.json
```

用编辑器在 `release.local.json` 填写实际 AppID，并将 `accountType` 设为该账号真实的工程类型。当前工程仅接受 `miniprogram`。该文件被 Git 和打包器排除。也可使用 `WECHAT_APPID` 与 `WECHAT_ACCOUNT_TYPE` 环境变量；环境变量优先。

AppID 校验只证明格式符合预期，不证明账号归属、权限、服务类目或上传资格。测试号和空白 AppID 不作为正式候选包输入。AppID 不需要私钥，发布时使用开发者工具内你的账号权限。

```sh
npm run release:check
npm run package:release
```

缺少 AppID、账号类型不符、版本冲突、缺模块或资源时，命令失败并说明原因。源码未配置真实账号时，这是实际阻塞，不能把源码检查通过当作正式发布检查通过。

成功时会生成 `.artifacts/release/` 下带版本的候选目录、ZIP 和哈希清单。AppID 只写入候选副本，不修改仓库项目配置。该产物仍标记为 `release-candidate`，平台编译、设备及审核状态保持未验证，不自动上传或发布。

候选 ZIP 脚本使用系统 `zip` 与 `unzip`。未提供这些命令的电脑可直接走上面的开发者工具导入流程；源码归档脚本使用 Git 自带的归档能力。

## 3. 在微信开发者工具完成最后一段

1. 在 Windows/macOS 安装微信开发者工具，登录有权限的微信账号。
2. 导入候选目录，核对目录直接包含 `app.json`、`project.config.json`，AppID 与账号类型相符。
3. 点击「编译」，确认控制台、WXML/WXSS、资源和代码依赖分析无阻塞；以工具实际包体检查为准。
4. 按 [WECHAT_IMPORT.md](WECHAT_IMPORT.md) 完成模拟器胜利、失败、技能取消、重开、前后台及导航验证，再进行 iOS/Android 真机确认。
5. 在开发者工具「上传」填写 `1.0.0` 和本轮说明；到微信公众平台核对开发版本、体验版、服务类目、主体资料和平台要求，再提交审核。
6. 审核通过后由有权限的账号执行发布。没有平台结果前，不把此版本标记为已发布。

发布说明可使用：

> 首个单人策略对战版本：三对三卡牌、龙焰与精准射击、自动对手决策、完整胜负结算与再战。支持前后台切换、离线对局与本地原创插画。

产品名称、图标、简介、客服与主体资料需要在账号后台填写真实信息。隐私事实和素材说明见 [PRIVACY.md](PRIVACY.md)，不要把示例值或未知资质填成已完成。平台如要求额外游戏类资质或调整应用类型，先完成该前置项，再提交。

## 4. 保存可以恢复的源码

通过验证后建立本地 Git 提交，再执行：

```sh
npm run archive:source
```

此命令要求干净的源码工作树，导出完整已提交源码 ZIP、可 `git clone` 的 bundle 和提交/哈希清单。它不会上传仓库或发布云环境。不要只保存原生导出包：导出包不含测试、设计源、文档和发布工具。

开发机若恢复到旧快照，可从 bundle 克隆完整源码，或者从源码 ZIP 恢复；Git bundle 恢复命令以工具输出/归档清单路径为准。下载并保存这两个源码产物，或将该提交同步到你自己的仓库；云环境快照另在环境设置中审阅、保存和发布。
